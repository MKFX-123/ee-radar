# EE Radar · 信息雷达

面向电子系同学的校园资讯与机会管理平台。把公开通知整理成可搜索的资讯、可核对的申请机会和可回溯的日程。

前端沿用 React + TypeScript + Vite，后端为 FastAPI + SQLite。正式页面读取真实采集数据，不混入演示样例。七个分类为：学业教务、科研科创、奖助评优、国际交流、实践公益、实习就业、校园生活；无法确定的内容显示待分类。

## 启动

建议 Node.js 22+、Python 3.11+。在项目根目录打开两个终端。

终端一，启动 API：

~~~bash
python3 -m venv server/.venv
server/.venv/bin/python -m pip install -r server/requirements.txt
server/.venv/bin/python -m server
~~~

API 监听 127.0.0.1:8000。首次启动导入 public/data/articles.json 中现有的真实采集结果，数据库保存到 server/data/radar.sqlite3（已加入 Git 忽略）。此后后台自动同步写入 SQLite，无需运行爬虫后再手动导入 JSON。重复启动不会重复入库，成功的模型结果在正文未变化时复用。

终端二，启动前端：

~~~bash
npm ci
npm run dev -- --port 5173 --strictPort
~~~

在浏览器访问 http://127.0.0.1:5173 。Vite 将 /api 请求代理到本地 API。若本项目已占用端口，直接打开现有页面，不重复启动。

~~~bash
npm run build
~~~

生产构建输出在 dist/。正式部署需要为 /api 配置反向代理；单独提供 dist 静态资源只支持离线快照。本轮没有部署或公开发布。

## 当前能力

- 首页：最新资讯、未来七天有明确依据的截止事项与活动、最后成功同步时间。
- 资讯：七大分类及待分类、关键词搜索、来源、人群、今天/近七天/近三十天、状态和收藏筛选；API 分页加载。
- 机会中心：复用同一条资讯，按类别和报名状态筛选。缺少可靠截止信息归入待确认，已截止不标为可报名。
- 日程：按周切换、日期跳转、活动/截止事项筛选，按日期范围请求关联数据，点击回到原资讯及时间证据。
- 详情：正文或已知摘录、发布单位与原始栏目、发布时间、采集时间、结构化事项、材料要求和原文链接。
- 信源：后台定时同步启用的来源，支持立即刷新；展示运行进度、增量统计、下次调度与各来源成功/失败状态。某来源失败保留已有数据。
- 助手：先检索数据库，附资讯详情与原文引用；没有匹配依据时明确说明。未配置模型时仅提供原文检索摘录。
- 本地操作：收藏、手动粘贴正文、删除、来源显示开关。手动资料只保存在当前浏览器，不会自动入库或调用模型。

## 自动增量同步

默认首次启动延迟 5 秒采集，此后每 15 分钟同步 crawler/sources.json 中 enabled 的信源，每来源最多处理 20 条近期记录。已有同步记录时，重启会沿用最近任务的时间安排。顶部“刷新数据”和信源弹窗的同步按钮可立即触发同一后台流程；反复点击或多进程同时触发会复用正在运行的任务。

按真实来源与上游 ID（info 的 xxid）及规范化 URL 去重，保留历史 URL 别名；比较正文和分析输入的哈希，只更新变化内容。列表摘录、空正文或旧快照不会覆盖已取得的较新全文。任务与历史资讯均保存在 SQLite，服务重启保留记录，并回收已退出进程的中断任务。

配置模型后，每轮额外处理最多 10 条新增、正文变化或待重试的资讯；相同正文的成功分析直接复用。失败分析采用指数退避，分析写回检查正文版本，避免旧结果覆盖新通知。未配置模型时保持待处理状态，继续展示原文和规则结果。

前端只轮询同步状态，后台数据版本变化后自动更新资讯、机会、详情和日程；断线时保留已显示的缓存，连接恢复后自动刷新。可以通过 .env.example 中的 EE_RADAR_SYNC_* 和 EE_RADAR_AI_BATCH_SIZE 调整周期、数量或关闭自动同步。当前文件锁适用于 macOS/Linux 本地部署，定时任务依附后端进程运行。

设计参考 [OneTHU 新闻接口与缓存实现](https://github.com/smartThise/OneTHU)：上游没有 since、更新时间或增量游标，因此采用近期分页回扫、稳定 ID 和正文哈希实现应用侧增量。此策略不保证找回所有历史或窗口之外的旧文修改。细节见 [自动增量同步说明](docs/自动增量同步.md)。

## 模型配置

推荐从页面配置：打开右下角 Radar 助手 → 模型配置，填写接口基础地址、模型名和 API Key，点击保存配置。保存后立即用于助手和资讯分析，不需要重启。

密钥保存在本机 server/data/model-config.json（仅当前系统用户可读写，已被 Git 忽略），不会返回浏览器或写入 localStorage。已配置时留空保留；切换到其他服务主机必须重新提供密钥。测试连接是独立按钮，点击后才发送一次最小请求，可能产生少量 API 费用，不发送校园资料。清除本地配置后回退环境变量配置。

也支持 .env.example 所列环境变量：

- EE_RADAR_AI_BASE_URL：兼容接口基础地址，通常以 /v1 结尾；服务追加 /chat/completions。
- EE_RADAR_AI_API_KEY：服务端密钥。
- EE_RADAR_AI_MODEL：获准使用的模型名。
- EE_RADAR_DB_PATH：可选的数据库路径。

不要将密钥写入 VITE_* 变量、前端代码或 Git。后端启动时自动读取根目录 .env，进程环境变量优先于 .env；页面保存的本地配置优先于二者。更改环境配置需要重启 API，页面配置即时生效。

配置完整时，后台同步会增量进行结构化分析，详情也可手动触发并缓存；问答在数据库检索之后调用模型。模型结果做类型、原文片段、日期及数值依据校验，失败时保留资讯，并回退可追溯的原文检索结果。

**本轮未配置真实模型密钥，因此尚未完成对真实资讯的模型调用验收。** 自动化中的模型成功/失败路径使用模拟响应，不等于真实模型可用。当前可见分类、事项与摘录由保守规则或原文直接产生，页面明确区分。

## 数据与采集边界

- 发布时间缺失时保持未知，不用采集时间替代；只有日期的事项不伪造 23:59。状态以 Asia/Shanghai 的当前时间计算。
- info 已做少量公开接口与详情验证；列表摘录不是完整正文。受限内容不绕过登录、验证码或风控。
- 官网中部分通知以附件承载主要内容；当前保留附件链接，不声称已读取附件或图片文字。
- 体育部官网与清华体育公众号是两个独立来源。公众号仅保留已配置/核实的公开文章，不承诺自动发现新文章或完整历史。
- 现有 crawler/policy.json 控制采集与展示的发布时间范围；本轮保留工作区既有策略。超出范围的历史库记录不做破坏性清除。
- API 不可用时，已有远程页面保留当前缓存；首次进入且尚无远程内容时使用离线采集快照。快照不代表刚刚同步。手动录入与收藏只在当前浏览器持久保存。
- 规则可能漏掉复杂时间和人群条件；未知值保持待确认，重要申请要求以原文为准。

## 主要接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | /api/health | 健康、数据数量与模型配置状态 |
| GET | /api/items | 分类、来源、关键词、人群、状态、日期与分页 |
| GET | /api/items/{id} | 详情、证据和原文 |
| GET | /api/opportunities | 同库机会筛选 |
| GET | /api/events | 按日期范围读取活动与截止事项 |
| GET | /api/sources/status | 来源同步状态 |
| POST | /api/sync、/api/sync/refresh | 发起增量同步，已有任务时返回同一任务与 reused=true |
| GET | /api/sync/status | 自动同步配置、运行任务、最近结果、下次调度、数据版本 |
| GET | /api/sync/{job_id} | 查看持久化同步进度与统计 |
| POST | /api/items/{id}/analyze | 可选模型结构化分析 |
| POST | /api/chat | 资料检索与带引用问答 |
| GET / POST / DELETE | /api/model/config | 查看非敏感状态、保存或清除本地模型配置 |
| POST | /api/model/test | 用户主动触发最小连接测试 |

页面使用 hash 路由：/#/、/#/feed、/#/opportunities、/#/schedule、/#/item/:id。

## 开源与 AI 使用

使用 React、React DOM、Vite、TypeScript、Lucide React、FastAPI、Uvicorn、HTTPX、Requests、BeautifulSoup。保留各依赖原许可；本轮由 AI 辅助修改，并使用已安装 frontend-design 与 frontend-design-review 作为设计和评审指导。
